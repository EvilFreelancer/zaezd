# MCP-шлюз и MCP Apps

## Три инструмента наружу

Три инструмента, а не двадцать. Claude Desktop и Codex работают на сильных моделях и двадцать инструментов переварят, так что дело не в выживании. Дело в том, что наружу торчит не набор чужих поисков, а осмысленный продуктовый контракт из трёх глаголов, найти поездку, раскрыть её, собрать оплату. Побочно это даёт цифру для слайда, манифест Tutu MCP весит 102 143 символа против нашего компактного.

| Инструмент | Аргументы | Возвращает |
|---|---|---|
| `find_event_trips` | `topics[]`, `origin`, `budget?`, `date_from?`, `date_to?`, `adults?` | событие, до трёх пакетов, справка о покрытии, ссылка на веб-версию |
| `get_trip_details` | `trip_id`, `package` | подробности пакета, отель, тарифы, погода если есть |
| `create_trip_checkout` | `trip_id`, `package` | чек-лист из двух-трёх ссылок с фактическим `kind` каждой |

Все три объявляют `outputSchema` и возвращают `structuredContent`. Это ровно та дыра Tutu MCP, которую мы измерили, и закрытие её одновременно даёт качество кода и снимает класс ошибок разбора у клиента.

Аннотации честные. `readOnlyHint: true`, `destructiveHint: false` у всех трёх, `idempotentHint: false` у `create_trip_checkout`, потому что ссылки протухают.

Последнее спорно, и спор записан в `docs/decisions.md`, а не замолчан. По букве MCP подсказка описывает отсутствие дополнительного эффекта на окружение при повторном вызове, а не свежесть ответа, и при `readOnlyHint: true` она вообще не имеет смысла. Значение оставлено как сигнал клиенту, что ответ нельзя переиспользовать, но это расширительное толкование, и оно названо своим именем.

## Целевые хосты

Продукт делается под два клиента.

| Хост | MCP | MCP Apps | Роль |
|---|---|---|---|
| Claude Desktop | да | да, `ui://` рендерится в песочном iframe | основной канал для виджета |
| Codex | да | проверить на месте, при отсутствии остаётся `structuredContent` | второй канал, текстовый |

Это меняет расстановку по сравнению с черновиком. Claude Desktop умеет MCP Apps штатно, значит виджет там не эксперимент, а рабочий интерфейс. Веб-страница при этом остаётся первичной, потому что судьи открывают публичную ссылку, а не ставят MCP себе в клиент.

Оба хоста работают на сильных моделях, поэтому подгонять формат ответов под ограничения маленьких моделей не требуется. Ставка делается на богатый `structuredContent` и на виджет, а не на минимизацию.

## Прощающая валидация входа

Небольшая, но полезная мера устойчивости. Каждый параметр-массив принимает три формы.

- настоящий массив `["ai","data"]`;
- JSON-строку `"[\"ai\",\"data\"]"`;
- строку через запятую `"ai, data"`.

Числа, пришедшие строкой, приводятся к числу. Вызовы без аргументов принимаются с пустым объектом и с отсутствующим полем.

Нормализация делается в одном месте, на границе, до композитора. Стоит это десяток строк, а снимает целый класс отказов, включая тот, на котором спотыкается сам Tutu MCP, где pydantic с `extra=forbid` роняет вызов на любом лишнем ключе.

## Ресурс MCP Apps

Один ресурс, а не три. Три самостоятельных `ui://` увеличивают число состояний и интеграционных ошибок, а судья всё равно откроет один экран.

```json
{
  "uri": "ui://zaezd/trip-board",
  "mimeType": "text/html;profile=mcp-app",
  "_meta": {
    "ui": {
      "csp": {
        "connectDomains": ["https://<наш-хост>"],
        "resourceDomains": ["https://cdn1.tu-tu.ru", "https://cdn2.tu-tu.ru", "<тайл-сервер>"]
      },
      "prefersBorder": true
    }
  }
}
```

Инструмент связывается с ресурсом через `_meta`.

```json
{
  "name": "find_event_trips",
  "_meta": { "ui": { "resourceUri": "ui://zaezd/trip-board", "visibility": ["model", "app"] } }
}
```

Протокол берётся готовым. У MCP Apps есть официальный пакет `@modelcontextprotocol/ext-apps` под лицензией MIT, версия 1.7.5 на 19 августа 2026 года. Он даёт серверные помощники `registerAppTool` и `registerAppResource` и браузерную сборку `app-with-deps.js`, готовую к подключению без сборщика. Писать JSON-RPC поверх `postMessage` руками не нужно, и это была бы ровно та самодеятельность, за которую ИИ-проверка снимает баллы.

Внутри iframe работает JSON-RPC поверх `postMessage`. Используем минимум.

| Метод | Зачем |
|---|---|
| `ui/initialize` | рукопожатие, получаем тему и размеры контейнера |
| `ui/notifications/tool-result` | получаем результат расчёта |
| `tools/call` | пересчёт при смене параметров |
| `ui/open-link` | открытие чекаута Туту во внешнем браузере |
| `ui/update-model-context` | сообщаем модели, какой пакет выбрал человек |

## CSP, главный практический риск

По умолчанию хост ставит `default-src 'none'`, и это ломает карту первой. Именно поэтому карта строится на Leaflet, а не на MapLibre. Leaflet рисует растровые тайлы обычными `img`, ему не нужны ни воркеры через `blob:`, ни WebGL, и вся его потребность в CSP сводится к `img-src` на тайл-сервер. Штатные иконки маркеров Leaflet тянутся относительным путём из его CSS и после инлайна дадут 404, поэтому маркеры делаются через `L.divIcon` с инлайновым SVG, растровых иконок в проекте нет.

Проверять надо внутри реального MCP-хоста, обычный браузер ограничений iframe не воспроизводит.

Порядок работы. Сначала веб-версия в обычном браузере, она первична. Потом та же страница в iframe с искусственно выставленным жёстким CSP. Только потом внутри настоящего агента.

Если карта в iframe не заводится, у MCP App остаётся статичная картинка карты вместо интерактивной, а интерактив живёт в веб-версии по кнопке "открыть полностью". Это запасной путь, который надо иметь заранее, а не изобретать на сцене.

## Подключение

Claude Desktop, через файл настроек.

```json
{ "mcpServers": { "zaezd": { "type": "http", "url": "https://<наш-хост>/mcp" } } }
```

Claude Code, одной командой.

```bash
claude mcp add --transport http zaezd https://<наш-хост>/mcp
```

Codex, через `~/.codex/config.toml`.

```toml
[mcp_servers.zaezd]
url = "https://<наш-хост>/mcp"
```

## Что шлюз не делает

- Не хранит состояние поездки на сервере. `trip_id` - это компактная кодировка параметров, а не ключ в базе;
- Не проксирует сырые инструменты Туту наружу, иначе смысл сжатия теряется;
- Не создаёт корзину на своей стороне. Ссылку открывает пользователь, корзина заводится в его сессии. Это юридическая модель Туту, и ломать её нельзя.
