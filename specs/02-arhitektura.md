# Архитектура

## Главное решение, веб первичен

Сдаются три публичные ссылки, и первая из них - работающий прототип. Виджет внутри Claude или Cursor такой ссылкой не является, судья его не откроет. Оба ревьюера сошлись на этом независимо.

Отсюда порядок приоритетов.

1. Публичный веб-экран, который открывается по ссылке в инкогнито и показывает готовую поездку;
2. MCP-шлюз, который отдаёт те же данные любому агенту;
3. Ресурс `ui://` с MCP Apps, который отдаёт тот же самый HTML внутрь диалога.

Целевые хосты для второго и третьего пунктов - Claude Desktop и Codex. Claude Desktop рендерит `ui://` штатно, поэтому виджет там рабочий интерфейс, а не эксперимент. Codex получает тот же результат через `structuredContent`. Третий пункт строится на уже готовом веб-экране, а не вместо него. HTML один и тот же в обоих каналах, иначе они разъедутся и баллы за UX пострадают именно там, где их считают.

## Компоненты

Четыре обязательных и три необязательных. Ревьюеры сошлись, что шесть подсистем на оставшееся время не собрать.

### Обязательные

**`src/sources/confcal.ts`.** Клиент к MCP каталога конференций. Держит `mcp-session-id`, переинициализируется при потере сессии. Ограничивает конкурентность одной сессии, параллельные вызовы через одну сессию не проверены.

**`src/sources/tutu.ts`.** Клиент к Tutu MCP. Сессия не нужна. Нормализует ответ в собственные типы в одном месте, дальше по коду сырой JSON Туту не ходит.

**`src/composer/`.** Ядро. Алгоритм дат, отбор событий, сборка пакетов, проверка выполнимости, расчёт полной цены. Детально в [04-kompozitor.md](04-kompozitor.md).

**`src/web/`.** Один экран trip board. Детально в [05-interfeys.md](05-interfeys.md).

### Необязательные, добавляются по мере времени

**`src/enrich/geo.ts`.** Геокодинг площадки через Nominatim и время пешком через OSRM. Деградирует до центра города с явной пометкой.

**`src/enrich/calendar.ts`.** Производственный календарь isDayOff, считает сгорающие рабочие дни.

**`src/enrich/weather.ts`.** Погода Open-Meteo только если дата попадает в окно прогноза в 16 дней, иначе блок не показывается вовсе.

Каждое обогащение - функция с таймаутом и фолбэком, а не сервис. Падение любой из них не должно ронять сборку поездки.

## Принципы, зафиксированные решениями

**Шлюз, а не прямое подключение из фронтенда.** Причины измеримые. Прямое подключение упирается в CORS. Манифест Туту весит около 25,5 тысяч токенов, а confcal добавляет свои четыре инструмента, и агенту нужен свёрнутый набор. Ответы Туту приходят строкой JSON внутри текстового блока, без `outputSchema`, и нормализацию всё равно надо делать в одном месте.

**Три инструмента наружу вместо двадцати.** Оба ревьюера отдельно отметили, что пять - всё ещё много для узкого сценария, а диаграмма и таблица в черновике расходились. Итог зафиксирован в [06-mcp-shlyuz.md](06-mcp-shlyuz.md).

**Мультитранспорт вместо четырёх поисков.** Холодный `search_rail` занимает до 6,3 секунды. `search_multitransport` даёт все четыре режима одним вызовом. Дальше постфильтр по времени прибытия делается у себя.

**Отели фильтруются локально.** Tutu не умеет искать отели по координатам, `search_hotels` принимает только `city_name` или гостиничный `geo_id`. Зато координаты приходят в листинге у каждого отеля. Значит ищем по городу события, сортируем по расстоянию до площадки сами.

**Гостиничный `geo_id` и транспортный - разные пространства.** Один неправильный id даёт пустой `hotels[]` при живом транспорте. Гостиничный id берётся только из предыдущего ответа `search_hotels`.

**Состояния поездки на сервере нет.** Никакого `refine_trip` с серверным состоянием. Рассчитанная поездка сериализуется в компактный идентификатор, по которому её можно открыть публичной ссылкой `/t/:id`. Переключение между вариантами - это выбор из уже посчитанных пакетов, а не пересчёт.

**Кэш в памяти с TTL плюс файловые фикстуры.** SQLite и три полноценных режима избыточны. Нужен `live` и `replay`, где `replay` читает записанные JSON из `fixtures/`. Фикстуры заодно работают как данные для тестов и как страховка на случай, если сеть на площадке подведёт.

## Стек

| Слой | Выбор | Обоснование |
|---|---|---|
| Рантайм | Node LTS, версия сверяется с хостингом до начала работы над интерфейсом | Node 24 может отсутствовать на выбранном хостинге |
| Язык | TypeScript | типы на границах читаются ИИ-ревьюером как качество кода |
| MCP | официальный `@modelcontextprotocol/sdk` | и клиент, и сервер |
| Веб | обычная страница со сборкой | MapLibre тянет воркеры и WebGL, "без сборщика ради iframe" ломается первым при CSP `default-src 'none'` |
| Карта | MapLibre GL, тайлы с атрибуцией | публичные тайлы OSM требуют подписи источника |
| Стили | выжимка токенов Kite локально | 384 КБ `index.css` с чужого CDN в демо не тянем |

## Публичная ссылка на рассчитанную поездку

Отдельное требование, которое стоит выделить. Судья должен открыть ссылку и увидеть готовый результат, не настраивая MCP и не дожидаясь внешних API.

Реализуется маршрутом `/t/:id`, где `id` - компактная кодировка параметров запроса. Страница сначала отдаёт записанный снимок, а живые ссылки на оплату пересобирает при клике, потому что `search_id` и `checkout_ref` Туту живут недолго.
