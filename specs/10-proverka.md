# Проверка, стенд и измерения

Документ описывает, как проверять, что продукт работает, и какие измерения выносить на слайд.

## Три канала, которые надо проверить

| Канал | Чем проверяется | Обязателен |
|---|---|---|
| Веб-страница | браузер, инкогнито, чужая сеть, три ширины | да |
| Ресурс `ui://` | Claude Desktop, там MCP Apps поддержаны штатно | да |
| MCP-инструменты текстом | Codex, `~/.codex/config.toml` | да |
| Регрессия на дешёвой модели | opencode, локальный стенд без квот | по желанию |

Целевые хосты - Claude Desktop и Codex. Claude Desktop основной, потому что рендерит виджет. Codex второй, там проверяется, что `structuredContent` читается без виджета.

## Дешёвый регрессионный стенд

Opencode с локальной моделью нужен не как целевой клиент, а как способ гонять проверки без расхода квот на Claude и Codex. Конфигурация уже собрана и лежит в `opencode.json` в корне.

```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "neuraldeep/qwen3.8-27b",
  "provider": {
    "neuraldeep": {
      "npm": "@ai-sdk/openai-compatible",
      "options": {
        "baseURL": "https://api.neuraldeep.ru/v1",
        "apiKey": "{env:NEURALDEEP_API_KEY}"
      },
      "models": { "qwen3.8-27b": { "tools": true } }
    }
  },
  "mcp": {
    "tutu":    { "type": "remote", "url": "https://mcp.tutu.ru/mcp",     "enabled": true },
    "confcal": { "type": "remote", "url": "https://confcal.rpa.icu/mcp", "enabled": true }
  }
}
```

Ключ берётся из `~/.coddy/.env`, переменная `NEURALDEEP_API_KEY`. Запуск.

```bash
set -a; . ~/.coddy/.env; set +a
opencode run -m neuraldeep/qwen3.8-27b "запрос"
```

Когда шлюз будет готов, в `mcp` добавляется третий сервер, а `tutu` и `confcal` отключаются. Стенд гоняет дымовой сценарий столько раз, сколько нужно, бесплатно.

## Что уже измерено

Три прогона одного и того же запроса на связке confcal плюс Tutu, 19 августа 2026. Главный вывод от выбора модели не зависит.

**Находка главная, модель недетерминирована в датах.** На одном и том же запросе про Kazan Digital Week 29-31 октября.

| Прогон | `check_in` | `check_out` | Ночей | Цена отеля |
|---|---|---|---|---|
| 1 | 2026-10-29 | 2026-11-01 | 3 | 12 000 ₽ |
| 2 | 2026-10-29 | 2026-10-31 | 2 | 7 800 ₽ |
| 3 | 2026-10-29 | 2026-10-31 | 2 | 7 800 ₽ |

Один и тот же отель, разные даты, разница в цене в полтора раза. Пользователь на одинаковом запросе увидит разные ответы.

Это прямое доказательство того, что алгоритм дат обязан жить в коде, а не в голове модели. Событие идёт с 29 по 31 октября, а сколько это ночей в отеле, модель каждый раз решает заново. Именно поэтому шаг 2 композитора описан формулой, а не пожеланием, и именно поэтому продукт не сводится к "подключите два MCP и поговорите с ними".

**Находка побочная, аргументы приходят в разных формах.** Во всех трёх прогонах массивы пришли JSON-строкой.

```
confcal_search_events {"topics":"[\"ai\"]","cities":"[\"kazan\"]","limit":10}
```

Параметр объявлен массивом, приходит строка. Сервер на pydantic с `extra=forbid` такое отвергает. Отсюда прощающая валидация на входе шлюза, описанная в [06-mcp-shlyuz.md](06-mcp-shlyuz.md). Мера дешёвая и на сильных моделях тоже не лишняя.

**Находка третья, грунтинг работает.** Модель сама подписала, что цена за всё проживание, а не за ночь, и в прогоне без данных честно отказалась их выдумывать. Правила вывода Туту работают, если их доносить.

## Дымовой сценарий приёмки

Прогоняется перед сдачей, вручную, по списку.

1. Публичная ссылка открывается в инкогнито и показывает рассчитанную поездку без действий пользователя;
2. Смена темы и города отправления пересчитывает результат;
3. Онлайн-событие не строит поездку и показывает отдельное сообщение;
4. Событие в городе отправления не строит поездку;
5. Вариант, не успевающий к открытию, помечен и не выбирается основным;
6. Полная цена содержит обе дороги и отель, цифры совпадают с разбором под полосой;
7. Кнопка чекаута подписана по фактическому `kind`, а не всегда "Купить";
8. Площадка, которую не удалось геокодировать, не имеет точной метки и подписана;
9. Отключённая сеть к одному из необязательных источников скрывает его блок, а не ломает экран;
10. Экран корректен на ширинах 360, 768 и 1280;
11. MCP-эндпоинт подключается в Claude Desktop, виджет рендерится, кнопка чекаута открывает внешний браузер;
12. Тот же эндпоинт подключается в Codex и отдаёт читаемый ответ без виджета;
13. Все три сдаваемые ссылки открываются у человека, который их не деплоил.
